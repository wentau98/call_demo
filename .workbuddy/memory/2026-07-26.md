# 2026-07-26

## iOS 视频通话 App - 编译错误修复

### 问题
GitHub Actions (Xcode 26.5) 编译失败，SwiftCompile 阶段报错退出码 65。
日志显示 SwiftEmitModule 失败，涉及 SignalingMessage.swift、SignalingClient.swift、SignalingHub.swift。

### 根因分析
1. **SignalingMessage Equatable 无法自动合成**：`.ice(from: candidate:)` 的 `[String: Any]` 类型中 `Any` 不遵循 `Equatable`，Swift 编译器拒绝自动生成 `==`
2. **GoogleWebRTC 1.1.31999 太旧**：2019 年的二进制包，iOS deployment target 8.0，与 Xcode 26.5 不兼容
3. **RTCAudioSession API 过时**：新版 WebRTC pod 不支持旧的 setCategory/setMode API

### 修复内容
1. **SignalingMessage.swift**：移除 `: Equatable` 声明，改用手动实现 `extension SignalingMessage: Equatable`，`==` 方法中 `.ice` case 忽略 candidate 字典比较
2. **Podfile**：`GoogleWebRTC 1.1.31999` → `WebRTC`（stasel 维护版本），platform 升至 `15.0`，添加 `post_install` hook 统一 deployment target
3. **WebRTCClient.swift**：
   - `RTCAudioSession` → 原生 `AVAudioSession`（`.playAndRecord` + `.voiceChat`）
   - 删除废弃的 `config.sdpSemantics = .unifiedPlan`（新版默认即 unifiedPlan）

### 第二轮修复（WebRTC delegate 签名 + 部署目标）

实际错误在本次构建才暴露：

1. **`RTCPeerConnectionDelegate` 所有方法签名变了**（stasel pod vs 旧 GoogleWebRTC）：
   - `didChangeSignalingState` → `didChange stateChanged:`
   - `didChangeIceConnectionState` → `didChange newState:` (type: RTCIceConnectionState)
   - `didChangeIceGatheringState` → `didChange newState:` (type: RTCIceGatheringState)
   - `didGenerateIceCandidate` → `didGenerate candidate:`
   - `didRemoveIceCandidates` → `didRemove candidates:`
   - 新增必选方法 `peerConnectionShouldNegotiate`

2. **`.dismiss` 需要 iOS 15**：部署目标 14.0 不够
   - `project.pbxproj` 中 `IPHONEOS_DEPLOYMENT_TARGET` 14.0 → 15.0（2处）

### 第三轮修复（stasel/WebRTC API 不兼容 - 本次）

stasel/WebRTC 大量 API 与旧 GoogleWebRTC 不同，本次修复 9 个编译错误：

**WebRTCClient.swift (8处)**：
1. `RTCDefaultVideoEncoderFactory` / `RTCDefaultVideoDecoderFactory` 不存在 → 使用 `RTCPeerConnectionFactory()` 无参构造
2. `.allowBluetooth` 已废弃 → `.allowBluetoothHFP`
3. `AVCaptureDevice.Format()` init 不可用 → 用 `guard let first = formats.first` 防护
4. `factory.peerConnection()` 返回非 Optional → 去掉 `guard let`
5. `pc.add(audio, streamIds:)` API 不存在 → 先试 `pc.addTransceiver(with:)`（也失败，见第四轮）
6. `pc.add(video, streamIds:)` 同上
7. `stopCapture {}` 多余闭包 → `stopCapture()`

**CallView.swift (1处)**：
8. `view.shouldMirroring = true` 属性不存在 → `view.transform = CGAffineTransform(scaleX: -1, y: 1)`

### 第四轮修复（addTransceiver 也不存在）

`pc.addTransceiver(with:)` 在此版 stasel/WebRTC 中也不存在。
`RTCPeerConnection.add()` 只有两个重载可用：
- `add(RTCIceCandidate)`
- `add(RTCMediaStream)`

改用 RTCMediaStream 方式添加本地 track：
1. `factory.mediaStream(withStreamId:)` 创建流
2. `mediaStream.addAudioTrack(addVideoTrack)` 添加本地 track
3. `pc.add(mediaStream)` 将流添加到 PeerConnection
